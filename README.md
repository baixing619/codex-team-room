# Codex Team Room

一个本地优先的 Codex 多成员项目协作界面。它把同一项目下的历史对话、团队公共聊天、知识条目、成员职责、模型配置与执行审批集中到一个房间里。

## 让 Codex 帮你安装

下载项目后，把 [CODEX_SETUP.md](CODEX_SETUP.md) 拖进 Codex。Codex 会先询问项目目录，然后调用仓库内固定的 Windows 安装器完成依赖重建、CLI 检查、本机服务和开机恢复，再创建当前用户自己的私人 Sites 与安全设备配对。不会让 Codex 临时拼装一串安装命令。

也可以直接双击根目录的 `install-team-room.cmd` 完成本机安装。安装器会按 `package-lock.json` 执行 `npm ci`，自动修复复制或移动目录造成的依赖断链；缺少 Node.js LTS 或官方 Codex CLI 时会自动安装。完整手机私人站点仍需把 [CODEX_SETUP.md](CODEX_SETUP.md) 拖进 Codex，完成一次所有者授权。

配对完成后，私有 Sites 可从手机发送消息、接收真实成员回复并处理一次性审批。本机代理只主动连接私人站点，不开放电脑端口；配对凭据保存在 `.team-room/`，受 Git 忽略且不会进入站点源码。

私人 Sites 是跨浏览器同步源：手机、电脑浏览器和本机 `127.0.0.1` 页面会同步项目房间、每房间成员配置与提示词、知识库、近期群聊和成员对话绑定。同步使用递增修订号；两台设备同时修改时不会静默覆盖，而会载入最新状态并提示重试冲突操作。

> 当前版本只在连接真实 Codex 运行时或已配对私人站点时允许发送。不会生成模拟成员回复、模拟命令或模拟完成状态。

首次打开主界面会显示四步基础教程；选择“不再显示”后可随时到“设置 → 重新显示基础教程”再次打开。完整操作见 [带真实页面截图的图文教程](docs/USER_GUIDE.md)。

## 双路线协作

Team Room 不是把所有请求都塞进一条长流水线，而是在同一个项目房间里连接多个彼此独立的 Codex 对话，并按任务选择两条真实路线：

- **快速路线**：简单任务或明确 `@某成员` 时，直接启动对应成员对话，不强制讨论。
- **协作路线**：复杂、多方案或跨职责的问题先由总控分析拆解；相关成员按顺序读取前序结论并提出、反驳或改进方案；总控比较后选择更优解，必要时再启动一个执行成员，最后由总控验收。

协作路线中，后发言成员会收到前序成员的完整输出。只有发现实质冲突、遗漏或风险时，才能以 `异议：` 开头提交异议并给出依据、影响和替代建议；没有实质问题时应直接确认或补充，不能为了异议而异议。总控会逐条判断异议，一旦拍板，运行时永久关闭本任务的异议窗口，不再接受分析委派。

成员卡片的“已收到、讨论中、执行中、回传中”只来自真实运行事件。关键词匹配不会提前把成员显示为工作中，超时或旧任务的迟到事件也不会伪造新的执行状态。

## 现在可以做什么

- 扫描本机 Codex 会话元数据，并按项目归类。
- 把已有项目接入为房间，继续查看原来的对话。
- 仅在用户点开某条历史对话时读取其可见消息。
- 将选定历史对话挂入当前房间的公共知识上下文。
- 为总控、开发、审核、资料四个成员分别配置模型、推理强度、职责和权限。
- 简单任务按明确提及直接处理；复杂任务先由总控规划，再用严格任务单激活讨论或执行成员。
- 用真实 App Server 审批事件和单写入锁控制命令与文件写入。
- 检测独立 Codex CLI；显式启用后，按成员模型、推理强度和权限创建并复用独立 App Server 线程。
- 把真实成员回复、任务完成和命令审批事件回流到公共群聊。
- 新消息、流式输出和审批状态更新时，聊天区域自动滚动到底部，不带动手机外层页面跳动。
- 支持图片、手机拍照、音频、文本与常见代码文件上传；图片/音频使用 App Server 原生输入，文本/代码由本机桥接安全内联，不依赖 Windows 只读沙箱启动命令。暂不接受 PDF、Office 和其他二进制格式，避免界面显示成功但 Codex 实际无法读取。
- 成员回复中的 `http(s)` 网页会显示为安全可点击的地址卡，常见远程图片可直接预览。成员只有用 Markdown 明确链接当前项目内的交付物时，电脑才会校验真实路径、文件类型、大小和敏感目录，再把文件上传到所有者私人 R2；图片显示缩略图，其他文件显示下载卡片，本机绝对路径不会进入站点。
- 每次真实成员任务都会携带同一项目的公共知识、近期团队消息、消息来源成员与来源对话 ID；不同成员仍保留各自独立的 Codex 对话。
- 在服务端执行单写入锁，阻止两个成员同时获批修改同一项目。
- 在浏览器本地存储房间配置；导出时自动排除聊天记录与命令记录。
- 在配对后把房间共享状态同步到所有者私人 D1；本地存储继续作为离线缓存。

## 本地运行

需要 Node.js 20 或更新版本。

```powershell
.\install-team-room.cmd
```

开发者手动运行时使用 `npm ci` 和 `npm run dev`。不要复制已经安装好的 `node_modules` 到另一个 Windows 目录。

默认会启动 Vite 本地服务。开发模式下，本地桥接层读取用户自己的 `CODEX_HOME`（未设置时为用户目录下的 `.codex`）。静态构建不直接包含本机桥接能力；启用设备配对后，本机代理通过经过认证的私人队列与站点通信，并继续由本地 App Server 执行任务。

为防止局域网设备访问项目路径，本地桥接默认只监听 `127.0.0.1`。只有明确设置 `TEAM_ROOM_HOST` 时才会改变监听地址；公开部署不应启用本地桥接。

```powershell
npm test
npm run build
npm run release:check
```

## 启用真实成员运行时

Team Room 不捆绑 Codex 可执行文件。需要真实成员线程时，请按 [OpenAI 官方 Codex CLI 安装说明](https://help.openai.com/en/articles/11096431) 单独安装并登录：

```powershell
npm install -g @openai/codex
codex login
```

Windows 上通过 npm 安装的官方 x64/ARM64 平台二进制会被自动识别。Team Room 不读取认证文件，也不靠受控命令环境推断登录状态；首次真实成员回合才是登录有效的最终证明。确认设置页显示 CLI 可用后，仍需由用户点击“启用真实成员”才会启动 App Server；Team Room 不会因检测到 CLI 而自动执行任务。

## 隐私边界

- 不扫描或批量上传本机项目文件、Codex 登录令牌、Cookie 或账号凭据；手机主动发送的消息、所选附件、成员回复和审批状态会进入所有者自己的私人 Sites 存储与队列。用户上传给成员的远程附件在任务结束后删除；成员明确交付且通过安全校验的项目文件会保留在所有者私人 R2，供跨设备预览或下载。
- 首页扫描仅读取会话元数据；对话正文按需读取。
- 不读取 Codex 的认证文件。
- 仓库不包含任何用户会话、真实项目数据或本机绝对路径。
- 公开发布前必须通过 `npm run release:check`。

更完整的说明见 [PRIVACY.md](PRIVACY.md) 和 [SECURITY.md](SECURITY.md)。
